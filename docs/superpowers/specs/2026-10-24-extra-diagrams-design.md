# Additional Mermaid diagram types

The user approved the next independent v2 slice: State, Class, Pie and Timeline, with the existing commit/push workflow. Accounts, gallery and line-map work are outside this slice.

Extend the shared registry with fixed indexes 5–8. Each type receives a representative sample, editable source with the existing configuration/interaction restrictions, local reset, focus annotations, Copy SVG and Mermaid Live links. The existing editor grid and phone views scroll through all available cards. Keep the landing proof to its original four types and render only that subset there.

Use the current serial Mermaid renderer, strict security, base theme and classic look. Keep TokenSet version 1 and existing share/saved-set formats. Reuse the mapped primary/secondary/tertiary fills for Pie and Timeline palette slots; leave absent roles derived. Export and preview must use the same variables and any trusted structural CSS. Timeline's event brightness filter is disabled in both so rendered colours match the theme being checked.

Contrast reads resolved Mermaid variables. State checks state text, transition labels, notes and transition lines; Class checks members, labels, notes and relationships. Pie checks percentage text on its three sample fills with the actual slice opacity, plus title/legend on the selected surface. Timeline checks its three sample colour groups and title. Focus leaders target corresponding real SVG elements. These remain representative theme checks, not a full audit of arbitrary custom source shapes or palettes.

Validate in Chromium using actual SVG colours on Paper, Ink and Brand, light/dark chrome, keyboard focus, source errors/reset, exports and narrow layouts. Unit tests cover registry/source boundaries, theme adapters and contrast math. No external services are needed; existing real-Postgres tests remain optional.
